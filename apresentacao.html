Módulo 1 • Arquitetura

Modelo Cliente-Servidor e Transporte TCP

Diferente de aplicações cliente-servidor tradicionais de consulta (como Web ou DNS), o Jogo da Velha opera como uma sessão interativa de estado contínuo.

Nó Servidor (Passivo / Peça 'O')

  • Inicia primeiro e anuncia os IPs locais no console.
  • Aloca o socket passivo na porta 6000.
  • Executa bind() e listen() aguardando conexões.
  • Ao aceitar o cliente com accept(), gera um socket de dados dedicado.
  • Realiza o sorteio da moeda (quem começa) e sincroniza com o cliente.

Nó Cliente (Ativo / Peça 'X')

  • Inicia após o servidor estar em escuta.
  • Pode receber o IP por linha de comando ou prompt interativo (Enter = 127.0.0.1).
  • Dispara o Three-Way Handshake através de connect().
  • Aguarda a mensagem de controle inicial de sorteio (recv()).
  • Entra em sincronia de turnos com o servidor.
🌐 Por que TCP e não UDP? O jogo exige ordem estrita de pacotes e garantia absoluta de entrega. Se uma jogada fosse perdida ou invertida em UDP, os tabuleiros ficariam dessincronizados e o jogo corrompido.
Módulo 2 • Camada de Transporte

O Ciclo de Vida Completo do Socket no Código

Mapeamento exato das funções da API Winsock2 chamadas no Servidor e no Cliente:

Servidor (Fluxo Passivo)

1
WSAStartup(MAKEWORD(2,2), &wsa) Carrega a biblioteca dinâmica ws2_32.dll no Windows
2
socket(AF_INET, SOCK_STREAM, 0) Aloca o descritor de socket passivo no Sistema Operacional
3
bind() & listen(sd, 1) Associa o socket à porta local 6000 e entra no estado LISTEN
4
accept() -> client_sd Bloqueia até o handshake terminar; retorna novo socket de dados

Cliente (Fluxo Ativo)

1
WSAStartup(MAKEWORD(2,2), &wsa) Carrega a pilha Winsock no processo cliente
2
socket(AF_INET, SOCK_STREAM, 0) Cria o socket ativo para estabelecer a sessão TCP
3
connect(sd, &servAddr, sizeof) Dispara SYN, aguarda SYN-ACK e envia ACK ao Servidor
4
send() & recv() / closesocket() Comunicação contínua em loop e encerramento com FIN-ACK
Módulo 3 • Estruturas de Rede

A Estrutura sockaddr_in e o Byte Order

Para interligar arquiteturas diferentes na rede, a convenção padrão é o Big-Endian (Network Byte Order).

C Code (Winsock)
struct sockaddr_in servAddr;

// 1. Familia de enderecos (IPv4)
servAddr.sin_family = AF_INET;

// 2. Endereco IP (INADDR_ANY no server ou inet_addr no client)
servAddr.sin_addr.s_addr = htonl(INADDR_ANY);

// 3. Conversao da Porta de Host para Network (16 bits)
servAddr.sin_port = htons((u_short)porta);

Funções de Conversão Cruciais:

  • htons() — Host to Network Short: Converte porta (16 bits) de Little-Endian (x86/x64) para Big-Endian.
  • htonl() — Host to Network Long: Converte endereço de 32 bits (ex: INADDR_ANY).
  • ntohs() — Network to Host Short: Converte porta remota recebida de volta para formato do host.
  • inet_ntoa() — Converte binário IPv4 em string legível (ex: "172.16.1.160").
  • inet_addr() — Converte texto pontuado para binário de rede de 32 bits.
⚠️ O que aconteceria sem htons(6000)? Na máquina x86 Little-Endian, o valor 6000 (0x1770) seria interpretado pela rede como 0x7017 (porta 28695). O cliente nunca conseguiria se conectar!
Módulo 4 • Usabilidade em Aula

Autodescoberta de IPs Locais (Sem ipconfig)

Em laboratório de redes com DHCP, o IP da máquina pode variar. O servidor descobre e exibe todos os seus IPs automaticamente:

servidor_velha.c
void exibir_ips_locais(int porta) {
    char hostname[256];
    gethostname(hostname, sizeof(hostname));
    struct hostent *host_info = gethostbyname(hostname);

    if (host_info != NULL && host_info->h_addr_list != NULL) {
        printf("[INFO] Enderecos IP para o Cliente conectar:\n");
        for (int i = 0; host_info->h_addr_list[i] != NULL; i++) {
            struct in_addr addr;
            memcpy(&addr, host_info->h_addr_list[i], sizeof(struct in_addr));
            printf("       -> %s (Rede Local)\n", inet_ntoa(addr));
        }
        printf("       -> 127.0.0.1 (se Cliente e Servidor estiverem no mesmo PC)\n");
    }
}

Como funciona na prática?

O ponteiro duplo h_addr_list armazena uma lista terminada em NULL de ponteiros para as interfaces ativas (Wi-Fi, Ethernet, adaptadores virtuais).

Vantagem durante a apresentação

O apresentador não precisa pausar, abrir prompt e digitar ipconfig. Ao iniciar servidor_velha.exe, o IP de conexão já surge na tela imediatamente!

Módulo 5 • Protocolo de Aplicação

Mensagens e Gramática do Protocolo de Jogo

Desenvolvemos um protocolo textual, leve e síncrono sobre o fluxo de bytes do TCP:

Mensagem Origem → Destino Semântica / Propósito
START:SERVER\n Servidor → Cliente Notifica o cliente de que o sorteio definiu que o Servidor ('O') joga primeiro.
START:CLIENT\n Servidor → Cliente Notifica o cliente de que o sorteio definiu que o Cliente ('X') joga primeiro.
MOVE:<1-9>\n Bidirecional Informa a célula do tabuleiro escolhida pelo jogador ativo (ex: MOVE:5\n marca o centro).

Por que mensagens com terminação \n?

O TCP é orientado a fluxo contínuo de bytes (byte stream), sem conceito nativo de fronteira de mensagem. O delimitador \n permite delimitar o fim do comando com clareza.

Sorteio Pseudoaleatório Imparcial

srand((unsigned int)time(NULL));
int vez_do_servidor = rand() % 2;
A semente do relógio assegura que cada execução sorteie quem inicia de forma genuinamente alternada.

Módulo 6 • Segurança e Validação

Leitura Robusta de Entrada: obter_jogada_usuario

Evitando armadilhas clássicas de C (Buffer Overflow, caracteres residuais, loops infinitos):

Código C - Sanitização
// 1. Leitura com fgets (limite estrito de bytes)
if (fgets(linha, sizeof(linha), stdin) == NULL) { ... }

// 2. Drena caracteres se ultrapassar o buffer
if (strchr(linha, '\n') == NULL) {
    int c;
    while ((c = getchar()) != '\n' && c != EOF);
}

// 3. Remove \r e \n
linha[strcspn(linha, "\r\n")] = '\0';

// 4. Remove espacos em branco nas pontas (trim)
// 5. Exige comprimento EXATO de 1 caractere ('1' a '9')
// 6. Impede marcar celula ja ocupada

Vulnerabilidades Eliminadas:

  • ❌ Uso de scanf("%d"): Se o usuário digitasse uma letra, scanf falharia e entraria em loop infinito. Resolvido com fgets!
  • ❌ Múltiplos dígitos (ex: 15, abc): Rejeitado pela verificação de strlen(inicio) == 1.
  • ❌ Quebras de linha Windows: Suporte tanto a \r\n quanto a \n puro.
  • ❌ Jogada sobreposta: O tabuleiro local é inspecionado antes de validar a entrada.
Módulo 7 • Regras do Jogo

Verificação de Vitória, Derrota e Empate

O tabuleiro 3x3 é mapeado em um vetor unidimensional de 9 posições (índices 0 a 8):

Matriz de Retas Vencedoras
int verificar_termino(const char tab[9]) {
    const int linhas[8][3] = {
        {0, 1, 2}, {3, 4, 5}, {6, 7, 8}, // 3 Horizontais
        {0, 3, 6}, {1, 4, 7}, {2, 5, 8}, // 3 Verticais
        {0, 4, 8}, {2, 4, 6}             // 2 Diagonais
    };

    for (int i = 0; i < 8; i++) {
        int a = linhas[i][0], b = linhas[i][1], c = linhas[i][2];
        if (tab[a] != ' ' && tab[a] == tab[b] && tab[b] == tab[c]) {
            if (tab[a] == 'X') return 1; // Vitoria Cliente
            if (tab[a] == 'O') return 2; // Vitoria Servidor
        }
    }

    // Se ainda resta espaco vazio
    for (int i = 0; i < 9; i++) {
        if (tab[i] == ' ') return -1; // Jogo ativo
    }
    return 0; // Empate ("Deu velha")
}

Validação Dupla e Independente

Uma boa prática essencial de sistemas distribuídos: não confie cegamente no nó remoto.

  • Tanto o Servidor quanto o Cliente executam a função verificar_termino() localmente.
  • Nenhum nó pode forjar uma mensagem de "você perdeu". O resultado decorre do estado sincronizado da matriz.
  • Se o adversário enviar uma jogada em casa já ocupada, a conexão é abortada por violação de protocolo.
Módulo 8 • Resiliência

Tratamento de Quedas e Fechamento Gracioso

Como o código lida com o fechamento intencional ou repentino da conexão TCP:

🟢

rc > 0 (Dados Recebidos)

O socket leu com sucesso rc bytes da rede. Colocamos o caractere nulo buffer[rc] = '\0' e fazemos o parsing da mensagem com sscanf().

🟡

rc == 0 (Fechamento Gracioso)

Indica que o outro lado fechou o socket ou encerrou o programa (o SO enviou o pacote TCP FIN). A aplicação avisa o encerramento sem acusar erro indevido.

🔴

rc < 0 (Falha ou Queda de Conexão)

Indica erro de I/O, cabo desconectado ou interrupção forçada (RST). O programa captura o código detalhado com WSAGetLastError() e libera a memória. 

Finalizacao Limpa (Teardown)
if (client_sd != INVALID_SOCKET) {
    closesocket(client_sd); // Transmite o pacote TCP FIN e fecha o canal
}
WSACleanup();                // Descarrega a biblioteca Winsock do espaco de enderecamento
Módulo 9 • Código-Fonte

Visão Comparativa do Loop Principal

Loop no Servidor
while (jogo_ativo) {
    if (vez_do_servidor) {
        int jogada = obter_jogada_usuario(tabuleiro, SIMBOLO_SERVIDOR);
        tabuleiro[jogada - 1] = SIMBOLO_SERVIDOR;
        exibir_tabuleiro(tabuleiro);

        snprintf(buffer, sizeof(buffer), "MOVE:%d\n", jogada);
        send(client_sd, buffer, (int)strlen(buffer), 0);

        int status = verificar_termino(tabuleiro);
        if (status == 2) { printf("Você venceu!\n"); jogo_ativo = 0; }
        else if (status == 0) { printf("Empate!\n"); jogo_ativo = 0; }
        else { vez_do_servidor = 0; }
    } else {
        int rc = recv(client_sd, buffer, sizeof(buffer) - 1, 0);
        // Parser MOVE:%d, atualizacao com 'X', checagem de vitoria e alternancia
    }
}

Loop no Cliente
while (jogo_ativo) {
    if (vez_do_cliente) {
        int jogada = obter_jogada_usuario(tabuleiro, SIMBOLO_CLIENTE);
        tabuleiro[jogada - 1] = SIMBOLO_CLIENTE;
        exibir_tabuleiro(tabuleiro);

        snprintf(buffer, sizeof(buffer), "MOVE:%d\n", jogada);
        send(sd, buffer, (int)strlen(buffer), 0);

        int status = verificar_termino(tabuleiro);
        if (status == 1) { printf("Você venceu!\n"); jogo_ativo = 0; }
        else if (status == 0) { printf("Empate!\n"); jogo_ativo = 0; }
        else { vez_do_cliente = 0; }
    } else {
        int rc = recv(sd, buffer, sizeof(buffer) - 1, 0);
        // Parser MOVE:%d, atualizacao com 'O', checagem de vitoria e alternancia
    }
}

💡 Simetria Elegante: A estrutura dos nós é espelhada. Ambos utilizam as mesmas funções de validação, renderização e encerramento.

Módulo 10 • Demonstração em Aula

Roteiro Passo a Passo para Demonstrar na Aula

Checklist para realizar a demonstração prática perante o professor e os colegas:

Cenário 1: Duas Máquinas no Laboratório (LAN / Wi-Fi)

  1. No PC do Servidor: Abrir o terminal e rodar .\servidor_velha.exe.
  2. Apontar para o IP exibido na tela (ex: 172.16.1.160).
  3. No PC do Cliente: Rodar .\cliente_velha.exe 172.16.1.160.
  4. Destacar o sorteio aleatório sendo impresso em ambos os terminais.
  5. Realizar jogadas válidas e demonstrar a tentativa de jogada inválida (letra ou casa ocupada).

Cenário 2: Na Mesma Máquina (Loopback)

  1. Abrir Terminal 1 e rodar .\servidor_velha.exe.
  2. Abrir Terminal 2 e rodar .\cliente_velha.exe.
  3. Pressionar Enter para aceitar o IP padrão 127.0.0.1.
  4. Completar uma partida com vitória e outra com empate para comprovar as duas saídas do algoritmo.
