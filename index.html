Módulo 1 • Estrutura de Dados

Representação do Tabuleiro em Memória

Decisão de projeto: Por que usamos um vetor unidimensional de 9 bytes em vez de uma matriz char tab[3][3]?

Definições Globais e Memória
// Simbolos imutaveis definidos por diretiva
#define SIMBOLO_SERVIDOR 'O'
#define SIMBOLO_CLIENTE  'X'

// Vetor de 9 caracteres alocado na pilha (stack)
char tabuleiro[9];

// Inicializacao com espacos em branco ' '
for (int i = 0; i < 9; i++) {
    tabuleiro[i] = ' ';
}

Vantagens Técnicas do Vetor Linear tabuleiro[9]

  • Mapeamento 1:1 Direto: A entrada do usuário é um número de 1 a 9. O acesso à memória é imediato: tabuleiro[jogada - 1] sem necessidade de calcular divisão e resto (linha = (n-1)/3, col = (n-1)%3).
  • Passagem Eficiente: Passado para funções por ponteiro simples (const char tab[9]), ocupando apenas 8 bytes de ponteiro no registrador da arquitetura x64.
  • Contiguidade de Memória: Otimização de cache L1 do processador na checagem das 8 linhas de vitória.

Defesa Contra Falhas Clássicas de C

  • Por que nunca scanf? Se o jogador digitar acidentalmente a letra "a" ou "teste", scanf("%d") falha na conversão, deixa os caracteres presos no buffer stdin e entra em loop infinito travando o terminal.
  • Controle de Limite com fgets: Lê no máximo 127 caracteres + '\0', garantindo impossibilidade física de Buffer Overflow.
  • Dreno de Linhas Longas: Se alguém colar um texto gigante, o while (getchar() != '\n') consome e descarta todo o restante, impedindo que suje a próxima rodada.
Módulo 4 • Tratamento de Strings

Função obter_jogada_usuario(): Trim e Validação

Tratamento de terminadores de linha Windows e validação estrita de caracteres:

Continuação da Função
        // 1. Elimina quebras de linha Windows (\r\n) ou Unix (\n)
        linha[strcspn(linha, "\r\n")] = '\0';

        // 2. Trim de espacos e tabs no inicio
        char *inicio = linha;
        while (*inicio == ' ' || *inicio == '\t') inicio++;

        // 3. Trim de espacos no final
        char *fim = inicio + strlen(inicio) - 1;
        while (fim > inicio && (*fim == ' ' || *fim == '\t')) {
            *fim = '\0';
            fim--;
        }

        // 4. Exige EXATAMENTE 1 unico caractere de '1' a '9'
        if (strlen(inicio) != 1 || inicio[0] < '1' || inicio[0] > '9') {
            printf("Entrada invalida! Digite apenas um unico numero de 1 a 9.\n");
            continue;
        }

        celula = (inicio[0] - '1'); // Converte char para indice 0 a 8

        // 5. Validacao se a celula ja esta ocupada
        if (tabuleiro[celula] != ' ') {
            printf("Posicao invalida! A celula %d ja esta ocupada (%c).\n",
                   celula + 1, tabuleiro[celula]);
            continue;
        }

        return celula + 1; // Retorna 1 a 9

O que esta lógica blinda na prática?

  • Espaços acidentais: Se o usuário digitar " 5 ", o algoritmo normaliza para "5" com sucesso.
  • Rejeição de números de dois dígitos: Entradas como "12", "0" ou "-1" são rejeitadas pela checagem strlen(inicio) != 1.
  • Conversão ASCII para Inteiro: A subtração (inicio[0] - '1') aproveita a contiguidade da tabela ASCII (código 49 a 57), transformando o caractere no índice do vetor (0 a 8) sem precisar de atoi().
Módulo 5 • Algoritmo de Regras

Função verificar_termino(): Matriz das 8 Retas

Implementação concisa e determinística da avaliação das 8 linhas vitoriosas:

servidor_velha.c / cliente_velha.c (Linhas 90 a 117)
int verificar_termino(const char tab[9]) {
    // Matriz estatica com as 8 combinacoes de indices de vitoria
    const int linhas[8][3] = {
        {0, 1, 2}, {3, 4, 5}, {6, 7, 8}, // 3 Horizontais
        {0, 3, 6}, {1, 4, 7}, {2, 5, 8}, // 3 Verticais
        {0, 4, 8}, {2, 4, 6}             // 2 Diagonais
    };

    for (int i = 0; i < 8; i++) {
        int a = linhas[i][0], b = linhas[i][1], c = linhas[i][2];
        if (tab[a] != ' ' && tab[a] == tab[b] && tab[b] == tab[c]) {
            if (tab[a] == 'X') return 1; // Vitoria do Cliente ('X')
            if (tab[a] == 'O') return 2; // Vitoria do Servidor ('O')
        }
    }

    // Se resta espaco vazio, a partida continua
    for (int i = 0; i < 9; i++) {
        if (tab[i] == ' ') return -1;
    }

    return 0; // Todas as 9 celulas cheias sem vencedor: Empate ("Velha")
}
🧠 Complexidade $O(1)$ Constante: Apenas 8 iterações de teste de igualdade direta. Sem alocação dinâmica, sem recursão e sem risco de vazamento de memória.
Módulo 6 • Setup do Servidor

Código: Inicialização e Fechamento do Listener

Trecho crítico de servidor_velha.c no gerenciamento dos descritores:

Configuração do Socket
// 1. Aloca socket TCP passivo
listen_sd = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);

// 2. Evita erro de porta presa no TIME_WAIT ao reiniciar
int opt = 1;
setsockopt(listen_sd, SOL_SOCKET, SO_REUSEADDR, (const char *)&opt, sizeof(opt));

// 3. Bind e Listen com backlog = 1 (apenas 1 cliente)
bind(listen_sd, (struct sockaddr *)&servAddr, sizeof(servAddr));
listen(listen_sd, 1);

// 4. Accept bloqueia e gera socket dedicado de dados
client_sd = accept(listen_sd, (struct sockaddr *)&cliAddr, &cliLen);

// 5. FECHAMENTO IMEDIATO DO SOCKET DE ESCUTA!
closesocket(listen_sd);
listen_sd = INVALID_SOCKET;

Por que fechar listen_sd logo após o accept?

Esta é uma das perguntas favoritas do Cel. Vidal!

  • O listen_sd tem como única função escutar o handshake inicial.
  • A comunicação com o adversário ocorre exclusivamente através do client_sd retornado pelo accept.
  • Como o jogo é estritamente de 2 jogadores, fechar o listen_sd protege o servidor contra conexões invasoras durante a partida e libera a porta no kernel do SO.

Como o Cliente consome esta mensagem em cliente_velha.c:

O nó Cliente inicia bloqueado na chamada recv(sd, buffer, sizeof(buffer)-1, 0). Ao receber os bytes, ele verifica com strstr(buffer, "START:CLIENT"). Se encontrar a substring, atribui vez_do_cliente = 1; caso contrário, atribui 0.

Módulo 10 • Resiliência de Sockets

Tratamento dos Três Retornos de recv()

Como o código diferencia recepção válida, desconexão limpa e erro fatal:

🟢

rc > 0 (Sucesso)

O socket leu rc bytes. O código imediatamente insere o terminador nulo buffer[rc] = '\0' para garantir que funções de string como sscanf e strstr não leiam lixo além dos bytes recebidos.

🟡

rc == 0 (FIN Gracioso)

Significa que o adversário fechou seu programa normalmente (o SO transmitiu o pacote TCP FIN). O código imprime mensagem avisando encerramento sem disparar alarme falso de erro.

🔴

rc < 0 (Erro / Queda)

Indica desconexão abrupta (RST), falha no enlace ou interrupção. O código captura o erro com WSAGetLastError(), rompe o loop e parte para a desalocação segura dos recursos.

Módulo 11 • Liberação de Recursos

Finalização Graciosa e Descarregamento da DLL

O que acontece após o término da partida em ambas as aplicações:

Trecho de Finalização
// 1. Fecha o socket de dados ativo disparando o handshake TCP FIN-ACK
if (client_sd != INVALID_SOCKET) {
    closesocket(client_sd);
}

// 2. Desregistra a aplicacao da pilha Winsock e descarrega ws2_32.dll
WSACleanup();

printf("Recursos liberados com sucesso.\n");
printf("Pressione Enter para encerrar o programa.\n");
getchar(); // Segura a janela aberta para visualizacao
return 0;

Por que WSACleanup() é obrigatório no Windows?

Ao contrário do Linux/BSD onde os sockets são arquivos no kernel, no Windows o Winsock aloca tabelas internas e referências à biblioteca dinâmica ws2_32.dll via contador de referências. O WSACleanup() decrementa esse contador e libera a memória alocada pelo WSAStartup().
